# Gallery requirements

**Status: Owner-approved scope and policy, 2026-11-08; G1a internal engine implemented; application integration pending.** Quantitative targets are provisional and unmeasured. [Owner decisions](gallery-decisions.md) govern scope; existing safety/resource constraints remain binding.

This accepted gallery annex follows the repository's ID-based “THE SYSTEM SHALL” style and expands REV-8. It does not change SAFE, REVIEW, MOVE or any accepted safety exception. G0 owner approval is recorded; the builder must reconcile the current code and execute G1a first. G1a now implements the internal advisory contracts and numeric policies; [verification](../verification/gallery-g1a-2026-11-08.md) distinguishes those tests from the remaining application, migration and hardware acceptance work.

## Scope and priority

**User story:** As someone with thousands of repetitive photos and screenshots, I want small, understandable groups and useful comparisons so I can review them faster without risking important files.

Priority P0 means required for the first local delivery; P1 means a separately gated learned enhancement; Later means not part of implementation approval. “Organizer” means virtual grouping and review, not moving source files into albums.

## Acceptance criteria

| ID | Given / when / then |
|---|---|
| AC-G1 — authorized scope | Given no permission, Selected Photos access, full media access, and foss all-files variants, when analysis starts, then only authorized eligible items are decoded; UI identifies partial/complete scope accurately. An unselected/inaccessible file is never decoded from an old cache entry. |
| AC-G2 — evidence firewall | Given arbitrary outputs including identical vectors, hash collisions, NaNs and hostile labels, when suggestions are generated, then classifier categories, exact witnesses, backup proofs and action permissions are unchanged. Static dependency rules and property tests must both enforce this. |
| AC-G3 — memories and explicit choice | Given camera/received MOVE items and REVIEW screenshots together, when grouped and ranked, then nothing is preselected; MOVE items cannot enter the review-trash plan; only explicitly chosen REVIEW items can reach its editable confirmation. |
| AC-G4 — useful suggestions | On the frozen held-out photo corpus, Balanced suggestions achieve pair precision ≥99%, with a cluster-bootstrap 95% lower confidence bound ≥98%, and reference near-duplicate recall ≥80%. Report coverage and each source/format stratum; no subgroup with adequate sample size may fall below 97% precision. Abstain or withhold the failing task/stratum. Best-shot hints are judged separately and do not control disposal. |
| AC-G5 — actions and accounting | Given Keep/Delete/Skip/Undo decisions, when the user finishes, then the usual confirmation contains exactly current, eligible REVIEW Delete choices; changing the list updates count/bytes. Cancel changes no file. Trash and measured-free-space results remain distinct; Undo restores actual trashed items. Test mode changes no source, asks no Android trash/delete action, and reports simulation. |
| AC-G6 — no-loss and keep-one | Given changed/missing/kept files, intersecting groups, sequential sessions and process death at any checkpoint, then protected files remain untouched, all-group disposal is refused, stale decisions cannot act, and actual recoverable dispositions satisfy the existing no-loss invariant. The keep-one guard checks the latest retained member versions at the choke point, not merely a cached UI count. |
| AC-G7 — lifecycle/failure | Given any E-G* case, then the stated safe fallback, bounded work, honest incomplete status and source-preservation behavior hold. Resume requires authorization recheck; persisted pending choices never count as a current-session confirmation. |
| AC-G8 — privacy/offline | Clean install + airplane mode + no GMS completes local analysis. With networking available and no backup running, analysis/clear/review produces zero app network connections or transmission. Package/source review finds no hidden telemetry. Clearing gallery data preserves backup/trash/kept records. Reports contain no feature vectors, captions, names or paths. |
| AC-G9 — resources | Meet the proposed owner/low-end latency, energy, total-memory/app-data and UI gates in gallery-benchmarks.md. Normal scan remains within its existing 60 s/10 s requirements and is not coupled to image inference. Any failed hard limit blocks the candidate, rather than being hidden by an average. |
| AC-G10 — accessible bilingual UX | All new screens are verified in en/he × light/dark, including 200% font, TalkBack and reduced motion. Text ≥4.5:1 contrast, large graphics ≥3:1, touch targets ≥48 dp, primary actions 56 dp. Physical swipe mapping and swap setting agree with existing H2b behavior. |
| AC-G11 — model earns admission | Compared on identical held-out corpus/devices, the selective learned hybrid adds ≥10 percentage points of near-duplicate recall at the same precision floor and reduces median target-workflow review time ≥20% with a 95% confidence interval showing improvement. It also meets AC-G13/14: its benefit cannot be established by embedding the entire library. All hard gates pass. Otherwise A remains the release candidate; shipping no model is a successful outcome. |
| AC-G12 — zero additional cost | Fresh offline installation, no account, no subscription/API credits and no billing setup provide the complete admitted gallery experience. Package/UI/dependency review finds no paid tier, provider client, remote model delivery or subscription bridge. Zero gallery network behavior still passes AC-G8. |
| AC-G13 — selective eligibility | Given resolved deterministic groups, no-match sources, unsupported images and ambiguous groups, only version-valid ambiguous participants may require inference. Every invocation has an allowed local routing reason; resolved-only runs have zero runtime initialization/inference. Changing a threshold cannot relabel the entire library as ambiguous without calibration evidence. |
| AC-G14 — global AI budget | Across many groups, shared participants, cache hits and rapid pause/resume, new unique image-version inference stays inside the single count budget and learned elapsed time includes initialization. Stop scheduling on limit; report any bounded single-item overrun. No per-group reset, automatic new run or background retry. Deterministic results remain usable and deferred work remains honest. |
| AC-G15 — incremental efficiency and keeper advice | Reopening unchanged authorized results causes no new decode/inference; +100 changes invalidate only the affected source versions and groups. A compatible cached participant is inferred at most once per source/model/preprocessing version. Each keeper recommendation cites actual measured facts; equal/ambiguous facts produce abstention, and recommending or changing the recommendation never changes any disposal checkbox or source file. |

Precision is the fraction of suggested within-group pairs that humans labelled as near-duplicates. Recall uses all labelled true near-duplicate relationships in the relevant reference subset, including ones candidate generation missed. These definitions must not be replaced by random-gallery “accuracy,” which is inflated by easy unrelated negatives. The benchmark protocol defines split, sampling and uncertainty handling.

## Existing invariants explicitly preserved

SAFETY-1…10, CLS-1/3/5/7, SAFE-4, MOVE-6/8/10/15, LOW-1…5, PRIV-1…7, SEC-*, MIG-1…5, NFR-1…6, P-1…3 and ADRs 0002/0003/0005/0006/0007/0008/0010/0011/0013 remain binding. New gallery suggestions create no permanent-deletion kind, no backup-verification shortcut and no additional network permission purpose. A new typed similarity-retention guard is additive; it must not reuse the existing exact-duplicate witness type with fabricated hashes.
