## Implemented contract and choices

`engine:gallery` uses existing JVM conventions and the already pinned coroutines dependency. Its internal entry receives an explicitly supplied inventory and a narrow `GalleryReadPort`; it cannot enumerate storage, mutate files or construct safety evidence. The app does not depend on this module yet.

1. Volume-scoped opaque source keys, revision/observation tokens, scan/run/permission identity and completed feature records. Weak size/mtime identity needs a fresh observation token; same-size/time replacement does not inherit old features. Adapters must revalidate before/after reads and callers must check current run at publication. Real provider identity handling belongs to G1b.
2. Nonempty size buckets request full-file SHA-256 records only for possible exact participants. Malformed/foreign digest records cannot establish equality; partial digests have no equality API. Exact groups remain advisory and skip visual decoding/quality ranking for identical bytes.
3. Global Hamming-band retrieval instead of a BK-tree: five dHash bands and seven pHash bands, with fixed radii no greater than 4/6. This has an uncapped radius-recall argument, not a measured photographic recall claim. Inspected postings (including duplicate postings), bucket storage and per-endpoint comparisons are bounded. A cap explicitly marks partial results and increments aggregate counters. Time/source dates are not mandatory relationship filters.
4. Stable ordering, disjoint groups, complete-link visual consistency, maximum 20 members. Low-detail/text-sensitive similarity is withheld; aspect mismatch is rejected. Text-sensitive sources can still form full-digest groups. The adapter must mark the supported stratum correctly. Flat/text and subtle-expression precision still need G2 evaluation.
5. Keeper advice uses provisional measured-fact margins: 25% usable-resolution advantage, 25% sharpness advantage with at least 0.05 absolute separation, or 0.05 less clipped fraction. A winner must dominate every rival without a conflicting advantage. Ties, missing/invalid facts and conflicts abstain. At most two factual reason codes; there is no selection state.
6. Four explicit route states; quality ties alone do not request AI. Conflicting plausible hashes may produce ambiguity, but the scheduling policy refuses uncalibrated work. Full policy values bind groups/calibration, including feature versions and thresholds, so changing a value cannot reuse the same decision identity accidentally.
7. Pure numeric learned-stage policy, without a model or runtime: one run-wide unique-participant reservation limit, 30 seconds including initialization/refinement, cache/shared-participant reuse, one in-flight item, cancellation/current-source checks, no failed-item retries, pause/resume preserving active elapsed time and counters, and early resolution. Reserve the whole missing participant set before loading; private reservation sets cannot be changed through a returned work list. Unused reservations remain charged conservatively. The adapter owns actual runtime lifecycle and must pause active timing when computation stops. There is no process-death persistence or automatic restart here.
8. Numeric dHash/pHash primitives over fixed-size canonical luminance inputs, with bit/DCT conventions pinned in code and golden tests. Android decode, orientation/colour/resize, real quality extraction and cache reuse are G1b work. No vector math/runtime is introduced just to test a nonexistent model.

The experimental profile is **not** a calibrated Balanced release setting. No recall, precision, latency, energy, memory or release target is marked passed by these choices.
