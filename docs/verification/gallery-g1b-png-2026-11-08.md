# G1b: limited PNG stream decoding

Date: 2026-11-08. Base: `ddf4a86d160f5fcd80c0be42c7830519f54ff9be`. This is one G1b increment; there is no gallery entry in the application.

The internal decoder consumes and closes a caller-provided stream. It accepts at most 8 MiB (reading one additional byte to detect overflow), validates PNG chunk CRCs and dimensions before bitmap decoding, limits chunk count to 4,096, rejects animated PNG and PNG EXIF, uses Android ImageDecoder with partial-image rejection, requests sRGB, bounds the decoded bitmap, recycles it, and checks coroutine cancellation around bounded operations. It reuses the canonical features from G1b-1. These limits are provisional, not measured resource or coverage guarantees.

The caller must authorize and revalidate the actual source, current permission and version before and after this primitive, run it off the UI thread, and implement source cancellation/close coordination and low-space/concurrency policy. The current code has no caller. JPEG, WebP, HEIF, motion media and all other formats are unsupported; lack of support must be reported as partial, never as a completed gallery scan. PNG EXIF is deliberately skipped until orientation can be established safely. Cancellation of a single blocked provider read or native decode is not guaranteed by this primitive.

Local Gradle `:core:gallery-android:testDebugUnitTest :testing:architecture:test spotlessCheck` passed: 6 new synthetic PNG tests and 7 existing canonical-pixel tests, plus architecture and formatting. Tests cover a valid PNG, CRC and compressed-data corruption, valid-CRC incomplete scanlines, truncation, trailing bytes, APNG and EXIF rejection, compressed-byte, chunk-count and source-pixel bounds, unsupported JPEG, cooperative cancellation and stream closure. The PNG unit tests use Robolectric native graphics. An instrumented valid/incomplete PNG test is added to the API 30/36 emulator workflow; `:core:gallery-android:assembleDebugAndroidTest` passed locally, and its execution is pending CI and it does not replace physical-device tests. No photographic accuracy, actual provider permission/version changes, physical device performance, low-space, memory peak or battery measurement is claimed. Full CI and review are pending.
