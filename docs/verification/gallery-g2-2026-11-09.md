# G2: evaluation tooling ready, baseline evaluation blocked

Date: 2026-11-09. Base: `07f054c` (work branch with G1a, the G1b PNG and JPEG decoders, `BoundedStillDecoder`, the schema 8 feature cache and the G1b coordinator with `GalleryGrouping.group`). Branch `g2-harness`, local, not yet a PR. Decisions C215–C219 in [progress](../progress.md).

**Summary.** G2 ("evaluate baseline", [gallery-tasks.md](../spec/gallery-tasks.md)) is **not done and not started as an evaluation**. Every G2 result needs a licensed or consented real-image corpus with independent human labels and physical phones, and none of those exist in this environment. This increment delivers only the developer-only tooling that a G2 session needs, plus this record of what is blocked and what unblocks it. No accuracy, latency, memory, energy or device result is claimed. No photo was downloaded, read, copied or committed. No threshold or grouping behaviour changed.

## What is ready (C215–C217)

- **`CandidateProbe`** (`engine:gallery`, C215): a read-only hook that `GalleryGrouping.group` calls for each source the hash-band index retrieves for a query, before any comparison or cap. It receives only versions the caller supplied, returns nothing and cannot change groups, routes, limits or counters. The app never passes one (`ArchitectureTest`).
- **Harness core** (`core/gallery-android/src/evaluation`, C216): corpus-index parsing and validation, opaque IDs (`"i" + sha256("keepclear-g2-id-v1\n" + relative path)[:16]`), the production pipeline (`BoundedStillDecoder` → canonical features → `GalleryGrouping.group` with `GalleryPolicy()`), status/skip-reason mapping, the scoring tool's CSVs and an aggregate timing/memory JSON. Compiled only into the module's JVM tests and instrumentation APK: the library AAR has no evaluation class (checked locally), and no main source refers to it.
- **`GalleryEvaluationHarness`** (androidTest): reads `-e galleryCorpus`, `galleryRunLabel`, `galleryPasses`, `galleryMaxImages`, `galleryDigests`; is skipped (JUnit `Assume`) without a corpus argument or directory, so CI stays green; writes to the test APK's external files dir; collects device identity, RAM, thermal, battery and power-save state; the instrumentation APK has no `INTERNET` permission (checked with `aapt2`).
- **Runbook** in [gallery-benchmarks.md](../spec/gallery-benchmarks.md#developer-evaluation-harness-and-runbook-g2-tooling-developer-only): adb build/install/push/run/pull/score commands and what to record. Developer-only; no user or owner acceptance step needs a computer.

**Synthetic smoke runs are pipeline correctness checks only.** Generated 64×48 PNG/JPEG patterns, a GIF signature, a truncated PNG and a missing file go through the real decoder, grouping and writers; the identical-pixel pair is grouped and retrieved as a candidate, the GIF is `unsupported_format`, the cut PNG `damaged`, the missing file `not_processed`. That a re-encoded JPEG joined the same synthetic group says nothing about real photos. These runs are not accuracy, recall, precision, timing or memory evidence and complete no part of G2.

## G3 consequence (C219)

[gallery-tasks.md](../spec/gallery-tasks.md) runs G3a only "if G2 justifies it", and ADR 0015 admits a model only after it beats the measured deterministic baseline (AC-G11). G2 has measured nothing, so no unresolved gap is known: **the G3 prerequisites are not met and G3 is not started.** No runtime, model, dependency or conversion work was begun. Shipping the deterministic baseline without a model is an accepted outcome under ADR 0015 and AC-G11; G4a can proceed on the deterministic baseline once its own gates allow, and G4b does not require G3.
