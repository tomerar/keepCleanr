## Test build for the phone (no computer needed)

Every push to `main` builds a signed `fossDebug` test APK once CI is green (workflow **CI**, job **Test APK (fossDebug)**). It is an Actions artifact, not a GitHub Release, kept 30 days. Install from the phone:

1. In the phone's browser (signed in to GitHub), open `https://github.com/tomerar/keepCleanr/actions/workflows/ci.yml?query=branch%3Amain`.
2. Open the newest run with a green check.
3. Scroll to **Artifacts** and tap `keepclear-test-<number>-<commit>.apk`. It downloads as an `.apk`, not a zip.
4. Open the downloaded file. The first time, Android asks to allow installs from the browser: **Settings › Allow from this source**, then go back and tap **Install**.
5. A newer test APK installs over the old one (same test key; see `keystore/README.md`). A future release build can't: uninstall the test build first, after restoring or emptying KeepClear's trash.

To build one on demand: Actions › CI › **Run workflow** on `main`.

**The test APK starts in test mode** (SAFETY-9): a banner on every screen says "מצב בדיקה – שום קובץ לא יימחק או יועבר". Cleaning, deleting, freeing space, restoring, emptying the trash and clearing caches only show what *would* happen ("would have freed X GB (test mode)"). Copying to a USB drive still works, because it changes nothing on the phone. To run the destructive checks at home, go to Settings › Advanced › Test mode and confirm twice. Turning it back on takes one tap.

### L6: private key for test builds (owner steps)

Today every test APK is signed with the public key in `keystore/`, so anyone can sign an update of "KeepClear test" that reads what it saved (including SMB and Nextcloud passwords). CI is ready to sign test APKs with a private key as soon as these four Actions secrets exist; until then the SMB and Nextcloud set-up screens of test builds say "use a test account".

1. On a computer with a JDK (`keytool` comes with it), make the key once (pick your own passwords; keep the file and passwords in your password manager, never in the repository):
   `keytool -genkeypair -keystore keepclear-test.p12 -storetype PKCS12 -alias keepclear-test -keyalg RSA -keysize 3072 -validity 9125 -dname "CN=KeepClear test"`
   (it asks for the keystore password; for PKCS12 the key password is the same).
2. Base64 it into one line: `base64 -w0 keepclear-test.p12 > keepclear-test.p12.b64` (macOS: `base64 -i keepclear-test.p12 -o keepclear-test.p12.b64`).
3. GitHub › the repository › Settings › Secrets and variables › Actions › New repository secret, four times:
   `TEST_KEYSTORE_BASE64` = the contents of `keepclear-test.p12.b64`; `TEST_KEYSTORE_PASSWORD` = the keystore password; `TEST_KEY_ALIAS` = `keepclear-test`; `TEST_KEY_PASSWORD` = the same password.
4. Run the workflow on `main` (Actions › CI › Run workflow). The "Private test key" step then says "Signing the test APK with the private test key", and the new test APK no longer shows the "use a test account" notice.
5. **Consequence:** an APK signed with the new key can't update one signed with the public key. On the phone, first open the old "KeepClear test", empty or restore its trash, then uninstall it, then install the new APK and set up the network places again.
